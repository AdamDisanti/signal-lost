# Tutorial graybox props

Four original low-poly models for Lawson's tutorial graybox. No asset packs or packages were added to the project. The source prefabs remain reusable visual props. The later [tutorial gameplay integration](tutorial-gameplay.md) adds pickup/healing behavior to scene instances without changing these source prefabs.

## Where to find them

In Unity's Project window, open **Assets > Prefabs > Enviornment objects > GrayboxProps**. The existing folder spelling is preserved.

| Prefab | Approximate dimensions at scale 1 (meters) | Included |
| --- | --- | --- |
| `CapybaraAstronaut.prefab` | 1.6 wide, 2.3 tall | Stocky capybara, blunt muzzle, small ears, ivory/teal spacesuit, open helmet frame, life-support pack, hoses; capsule collider and `DialogueAnchor` |
| `BurntRockBasin.prefab` | 2.5 wide, 2.1 deep, 1.1 tall | Charred faceted rock, recessed basin, static concave mesh colliders and `MiningLaserAnchor` |
| `AlcoholFlask.prefab` | 0.19 wide, 0.32 tall, 0.09 deep | Metal flask, grip, orange label, screw cap and retaining hinge; box collider and `GripAnchor` |
| `GrayboxExitGate.prefab` | 4.3 wide, 3.2 tall, 0.9 deep | Open sci-fi frame, directional arrow, control panel, collision around the frame only, and `ExitAnchor` |

Drag the **`.prefab` files**, rather than the FBX files in `Models`, into your scene to get the materials, colliders and anchors. All roots have a ground-level pivot and unit scale; Unity Y is up. The character and flask label face local +Z. The gate passage runs along local Z.

### Capybara

A static, unrigged Cavendish placeholder. The visor is represented as an open/raised frame so the animal's face remains visible. No dialogue, NPC behavior, skeleton, animations, or quest scripts are included.

### Burnt rock / mining laser placement

Expand the prefab instance and find **MiningLaserAnchor**, located 0.67 m above the root. The basin floor is at 0.64 m; the opening is approximately 1.4 by 1.1 m at the rim and narrows toward the floor. Parent your laser visual under the anchor and adjust its local position/rotation for its own pivot and size. **A mining laser is not included in this prop.**

The rock uses non-convex mesh colliders so the recess remains open. Keep it stationary; do not add a dynamic Rigidbody or turn its collider into a convex hull, which would fill the basin.

### Flask

Realistic handheld scale, so it may look small next to the graybox. Select it and press F in Scene view to frame it. No drinking, healing, pickup, inventory, or Rigidbody behavior is attached to the source prefab. In `Tutorial.unity`, E picks up the placed flask and F drinks from a non-colliding first-person copy; see [tutorial gameplay](tutorial-gameplay.md).

### Gate

The opening is about 2.8 m wide between posts (2.54 m between the feet) and 2.8 m high. It has no collider across the passage and no threshold. **It will not cut a hole in an existing wall.** Make a matching gap in your graybox wall, then position the gate there. There is no automatic opening, unlocking, level loading, or progression trigger. `ExitAnchor` is only a placement marker.

## Asset maintenance

- Geometry is generated by [create_graybox_props.py](../tools/blender/create_graybox_props.py), tested with the locally installed Blender 5.3 beta. No fonts, textures or third-party models are used.
- Generate into a **new scratch directory**, not over hand-edited sources:

  ```text
  blender --background --python tools/blender/create_graybox_props.py -- --output <scratch-directory> --render
  ```

- Keep edited `.blend` sources outside Unity `Assets`. Export selected meshes as FBX, using scale 1, -Z Forward and Y Up; preserve the existing FBX `.meta` files when replacing model contents. The generator bakes space transforms for these static meshes.
- Prefabs reference their FBX models and shared URP/Lit materials. Re-exporting a model with different part names or hierarchy may invalidate prefab overrides; inspect the prefab afterward.
- **Signal Lost > Graybox Props > Create Missing Prefabs** creates only absent prefabs/materials. It does not overwrite existing ones or edit your open scene. The builder requires the four FBX files and `Models/Palette.json` already imported.
- **Signal Lost > Graybox Props > Validate Prefabs** checks references, scale, ground pivots, URP materials, basin collision and gate clearance. The result is written to the ignored `signal-lost/Logs/GrayboxPropsValidation.txt`.
- `.blend`, `.fbx`, and preview `.png` files are covered by the repository's Git LFS rules. Prefabs, materials, scripts and `.meta` files remain ordinary text. No files were staged or committed by this task.

## Validation performed

- Blender generated and rendered all four models; every component passed a manifold-edge check and normals were recalculated before export.
- Unity **6000.6.2f1**, with URP **17.6.0**, compiled the builder and imported all four FBX files in an isolated temporary project. All prefab mesh/material references, ground pivots and scale checks passed.
- In that project's **Play Mode**, a 1.8 m CharacterController passed through the gate opening and stopped at a gate post and the capybara. Raycasts hit the recessed basin floor at 0.64 m and the flask collider.
- The scratch-only [Play Mode smoke harness](../tools/unity/PropPlaySmoke.cs) is kept outside `Assets`. To repeat, copy it and the prop builder into a disposable project's `Assets/Editor`, copy the prop asset folder with its `.meta` files, use the same Unity/URP versions, and launch Unity with `-batchmode -nographics -projectPath <temporary-project> -executeMethod PropPlaySmoke.Start -logFile <log-path>`. Omit `-quit`; the harness exits after its Play Mode checks. It refuses to run outside the system temporary directory or without batch mode.
- Asset/folder `.meta` pairs and GUID uniqueness/references were checked. Git LFS attributes cover the binary files; validation logs remain ignored.
- Your active tutorial scene was not modified or interactively playtested. Blender previews are not a substitute for checking final lighting, placement, or collision after arranging these props in your own scene.

## Scope decisions

The request establishes the rock basin and exit gate as visual tutorial props. Gate unlock requirements and exit destination remain unspecified; no progression rules were invented. Dialogue remains outside this asset task. Drinking and pickup were subsequently integrated into `Tutorial.unity`; see [tutorial gameplay](tutorial-gameplay.md) for the current controls and behavior.
